# 一斉停止と一斉再開

**1行**: 自律稼働をまとめて止め、**何が動いていたか**を状態ファイルに記録し、その記録から停止前の状態へ正確に戻す。停止と再開は**対で1つの制度**として設計する。

## 世界標準の名前

Kill switch / emergency stop（EU AI Act 第14条(4)(e) の stop button）＋ maintenance mode ＋ state snapshot ＋ restore from snapshot / desired-state reconciliation ＋ rollback の runbook。

## 発火（何がこれを動かすか）

人の明示操作のみ。**クロックでの自動再開はしない**（容量や状況の確認は人にしかできない）。

## 停止側の要件

- 自律ループ・定期ジョブ・再点火フラグをまとめて止める
- **何が動いていたかを状態ファイルに記録する**（これが無いと正確に戻せない）
- 冪等（既に停止中なら何もしない。正本の設定を空で上書きしない）
- 計画だけ見る乾式実行を持つ
- 外部の利用者に影響するジョブが混ざっていないかを一度確認してから止める

## 再開側の要件

- 状態ファイルの記録どおりに戻す。**動いていなかったものは点けない**
- 状態ファイルが無ければバックアップからのフォールバックに落ちる

## 実測 / 観測

完了条件は実出力で定義する。停止側 = 有効な定期ジョブ0件・稼働ループ0。再開側 = 停止前の件数に戻ったこと ＋ ループが動き出したことの目視。**文章だけの「止めた」「戻した」は不可**。

## 注記

起源は、複数サービスに触る一括操作を手打ちで行い、**stop だけして start を忘れ、11個のサービスが2日間止まった**事故。以後、この種の一括操作は「状態を記録して戻せるスクリプト経由でのみ行う」を規約にした。
