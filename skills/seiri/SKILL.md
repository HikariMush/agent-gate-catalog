# seiri — 思考の整理

対訳: **GTD（capture / clarify / organize / reflect / engage）＋ faceted classification（Ranganathan）＋ prototype theory（Rosch）**。

前提: 整理は「頭の中で考える」ことでは達成できない。人間の作業台（作動記憶）は同時に4個前後しか載らないので、抱えているものが5個以上ある時点で物理的にオーバーフローしている。**先に全部外に出す**以外に道はない。

## 入口は3つ（症状で選ぶ・全段階を毎回通さない）

| 症状 | 入口 |
|---|---|
| 何を抱えているかすら見えていない | **[0] から**（全段階） |
| 何があるかは分かるが動けない | **[5] から** |
| 対象が1件に決まっている | **[8] から** |

## [0] 判定・宣言

どの入口かを判定し、**一言で宣言してから始める**。出力先のファイルを1つ決め、以後の全記録をそこに積む。

## [1] 収集（ダンプ）★最頻の事故地点

**チャットに返すのは相槌だけ。** 分類も回答も提案も一切しない。裏のファイルには全量を書き続ける。

- **質問形で来ても、それはダンプの1項目**。迷ったら相槌に倒す
- 順不同・大小混在・公私混在で受ける。整理させない
- 本人の言葉を**原文のまま**保持する（後の段階で本人の語彙が効く）

## [2] 出し切りの補助

出が止まったら、未出の棚を提示する（身体・体調 / 仕事の気がかり / 金の不安側 / 人間関係 / 期限が迫っているもの / 返していない連絡）。

## [3] 分類 — 排他の箱を作らない

**軸を複数立てて多重タグにする。** 1項目1箱に押し込むと、必ず「これは A でも B でもある」で詰まる。

1. 対象群を眺め、説明に自然に使っている観点を軸として抽出する
2. 項目×軸の表を作り、該当する軸すべてに印を付ける
3. **濃い交差点を名指しする**（複数軸にまたがる項目は、その人の中心にある問題であることが多い）

分類が割れないのは分類者の失敗ではない。カテゴリは本性的に境界が曖昧で、**きれいに切れる方が例外**。

## [4] 構造の発見（仮説を立てる・まだ本人に当てない）

束と束の関係を読み、**共通の核の仮説**を1つ立てる。この段階の産物は未検証なので、裏のファイルに置き、[5] で確認が取れるまで前提にしない。

## [5] 対話（核を確定させる）

チャットに出してよいのは「観測事実・質問・本人が確認済みの解釈」の3つだけ。

- **肯定側**: 何を求めているのかを、本人の言葉の再配置だけで示す
- **批判側**: 構造的な問題を2点まで。配慮より正確さを優先する
- **確認の質問**: 仮説は必ず疑問形で当てる。肯定も否定もされていない解釈を前提に次を組まない
- **本人の答えが枠を壊したら、枠を捨てる**
- 実測質問を出したら**足さずに待つ**

## [6] 敵対監査（求められたら）

確定した核に対して、現状の脆弱性を打撃度順に並べる。各件「症状 / 実測値 / 機序 / 最小の直し」。ただし**環境の制約と認知の歪みを取り違えない**（「選べなかった」のか「選ばなかった」のかは全く別）。

## [7] 仕分け（5つの行き先・宙吊りを残さない）

済 / 走行中 / AI側の未着手キュー / 人間ゲート（外向き・不可逆・お金）/ **再評価トリガーを明示できた保留のみ**。「いつか考える」は保留ではなく宙吊り。

## [8] 着工（1件ずつ・ここから並列）

1. その1件について、最小限の確認質問（2〜3個まで）。目的と判定条件を取る
2. **手段を先に聞かない**。目的・数字・期限を先に取る
3. **要件を `REQUIREMENTS.md` に番号付きで固定**してから発注する
4. 発注の**禁止制約は間接実行込みで書く**（「これらを内包するスクリプトの実行も禁止」）
5. 投げたら次の1件へ。待たない

## [9] 検収・報告

**実出力を貼る**。**自分の成果物に自分で合格を出さない**。報告には「次に誰が何を」まで書き、本人のアクションが無いなら「アクション: 無し」と明言する。

## やってはいけない（実走で実際に叱責された5件）

**この禁止事項が、上の手順書より効く。**

1. **ダンプ中に回答する** — 質問形の項目に答え始めた瞬間に流れが止まる
2. **壁打ち・探索の最中に設計判断や裁定、リスクの枠出しをする** — 「壁打ち」「思考の整理」「考察したい」は発散のトリガー語。短く映し返して問いを1個返すのが上限
3. **整理を放り出して実装に飛ぶ** — 面白い実装に着手した時点で消化した気になり、残りが丸ごと後回しになる
4. **推測で埋める** — 足りないなら質問する。躊躇の原因は「完成品を出したい圧」「自分の仮説への回収」「待つことの回避」の3つ
5. **長い返答** — 認知負荷を下げるための道具が認知負荷をかけるのは自己矛盾

## 完了条件

全項目が5つの行き先のどれかにある（宙吊りゼロ）／**共通の核が1つ、本人の確認つきで書かれている**／着工した案件は要件が番号で固定されている／ダンプの全量が1ファイルに残っている。
