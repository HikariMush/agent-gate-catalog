# l2package — 案件を1枚に畳んで残す

対訳: **lessons learned register / project closeout（PMBOK）＋ blameless postmortem（成功案件版）＋ reusable asset**。

目的: 問題解決を毎回パッケージ化する癖を仕組みに固定する。1案件クローズ ＝ 1枚。貯めると (a) 再利用部品が複利で積む (b) 「業種タグ × 痛みの型タグ」の交差で、次に売れるものが見える。

## 鉄則

1. **軽さが命** — 13行。重くすると癖が死ぬ。埋まらない欄は「不明」で可
2. **書く引き金は案件クローズ**（納品・受注の節目）。ここでしか正確に書けない。着手中には書かない
3. **タグ2軸は厳密に**（表記ゆれ厳禁・新タグは既存に寄せる）。ここが崩れると索引が死ぬ
   - 業種タグ: 機械設計 / 店舗什器 / 資格 / コーチング / 営業 / EC / 士業 / 飲食 など
   - 痛みの型タグ（業種横断）: 文脈喪失 / 反復作業 / 属人化 / 可視化不足 / 連携断絶 / 入力負荷 / 判断遅延 など
4. **罠の欄は必ず埋める**（正直に。次回避けるため）。称賛ではなく事実
5. **再利用部品は「業種非依存か否か」を意識して書く**（業種を跨ぐ部品が次の商機になる）

## 工程

1. **文脈を集める** — 会話・成果物・決定ログから13行を埋める材料を拾う。分からない欄は1〜2個だけ確認する（全部聞かない）
2. **13行を書く**
3. **採番** — 既存の最大番号 + 1（4桁）。ファイル名 `NNNN-slug.md`
4. **索引を更新** — 表に1行追記（ID / 業種 / 痛みの型 / 規模 / 反復 / 保守 / サマリ / リンク）。反復件数は既存索引を数えて記入する
5. **一言の所見** — 「このセルは何件目・横断性はあるか」を1行だけ添える（貯まっていなければ「まだ判断は早い」でよい）

## 13行の書式

```
── L2パッケージ ──────────────
日付 / 依頼主[業種タグ] / 一言サマリ

■具体(解いた事)
・痛み(客の言葉)：
・理想(言語化)：
・作った物：
・決め手(効いた1点)：

■抽象(次に使える)
・痛みの型[タグ]：      ← 業種を跨ぐ横串
・解き方の型：
・再利用部品(流用/新作)：

■再利用条件
・次に引く合図(どんな客/痛み)：
・罠(次回避ける)：

■メタ(1行)
・反復[業種◯件目/痛みの型◯件目]・規模[小中大]・保守[有無]
─────────────────────────
```

## 対訳の注記（正直に）

台帳の部分（lessons learned register / project closeout / reusable asset）には確立した名前がある。一方、**「業種タグ × 痛みの型タグの2軸で交差セルの反復件数を数え、業種非依存の部品を次の商機として検出する」使い方に対応する確立名は見つかっていない**。近縁として software 側の usage pattern mining があるが、対象がコードであって需要ではない。

## やらないこと

コードのリファクタや汎用ライブラリ化の「パッケージ化」（別物）／着手中の案件の途中経過記録／全欄の根掘り葉掘りのヒアリング
