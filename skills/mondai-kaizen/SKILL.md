# mondai-kaizen — ベンチマーク駆動でコンテンツの質を上げる

> **この手順は自前の台帳・検査スクリプトを前提とする。** 同梱していないので、無い場合は同じ項目を手動で確認する（何を確認すべきかは各手順に書いてある）。

対訳: **competitive benchmarking / gap analysis ＋ quality gate ＋ deterministic-first（"use an LLM last, not first"）／ model cascade**。

`franchise-kaizen`（旗艦深掘り → マニュアル化 → 全店展開）の**コンテンツ版**。あちらが明示的にスコープ外にした「コンテンツの質」を、外部ベンチマークを起点に埋める。

| | franchise-kaizen | mondai-kaizen |
|---|---|---|
| 対象 | エンジン・UX・データ設計 | 本文・選択肢・解説・周辺知識・難易度（中身の質） |
| 起点 | 自陣の旗艦を深掘り監査 | **競合/理想形のベンチマーク分析** |
| 後半 | 自前で展開・還流 | **横展開・還流は franchise-kaizen に接続** |

## 鉄則

1. **採点器が先（測れないものは上げられない）**
   最初に「改善の前後を数値で測る仕組み」を立てる。解説の字数・誤答ごとの解説率・根拠の明示率・空欄の数など、前後が出る指標。これが無いと「良くしたつもり」で終わり、劣化にも気づけない。この指標はそのまま最後の品質ゲートに育つ

2. **コスト最小の順序を守る（決定論を先に使い切る）**
   「API でいくら」ではなく「**AI に頼る量そのものをどこまで削れるか**」で設計する。削減の5層を上から順に使い切る。
   - 層1 **AI ゼロの機械生成**（構造化資産＋テンプレ）— **必ず最初に実測する**。何件がこれで賄えるか数える
   - 層2 導出（既存メタの再配置・実測値からの計算）
   - 層3 AI 生成は全件やらない（頻出＋誤答実績で刈り込む）
   - 層4 残りは定額枠のバッチで、正本突合つき
   - 層5 エンジン改修は1回書いて全店へ機械展開
   世界側の言い方では **deterministic-first**（まず決定論版を作り、失敗する箇所にだけ LLM を足す）。出力の形が固定でデータだけ変わるなら生成ではなくテンプレートを使う

3. **AI が触る事実は正本突合が必須**
   AI が生成した数値・条文・用語は、生成後にスクリプトで構造化資産と機械突合する。突合を通らなかった残差だけを人が監査する。「AI が AI を監査する自己参照」に落とさない。機械生成（層1）は正本一致がスクリプトで証明できるので監査コストもほぼゼロで、だから最優先になる

4. **実装者 ≠ 検収者**
   実装したセッションは合格を出せない。新鮮な目に「合格ではなく穴を探せ」と発注する。指摘は中以上すべて反映してから次段へ

5. **ゲート化で締める（二度と無言で劣化させない）**
   採点器を、再起動時に必ず走る品質ゲートに変える。**床（空欄0・劣化検知・混入0・正本突合）だけをゲートにし、字数平均などの代理指標はゲートにしない**（ラチェットは水増しを誘発する）。基準値は現状で凍結して初日から効かせる。旧経路が残っていればゲート付きへ委譲してバイパスを塞ぐ

## 工程（7フェーズ）

0. **基準設定** — ①ベンチマーク ②品質軸（今回どれを上げるか）③対象範囲。網羅性の台帳で現在地を見て、今回埋めるマスを宣言する
1. **ベンチマーク分析 ＋ 自陣の定量スキャン（→ギャップ表）** — ベンチの**現物**を観点分解する（推測でなく実際に見る）。自陣は全件横断で定量スキャンする（1スクリプトで全体を開き数値化）。旗艦だけ見ない。既存のロードマップと照合し、**既知項目は落とす**（新規性のある差分だけが価値）
2. **コスト最小の実測** — 層1 を**この場で実測**する。構造化資産を読み、「テンプレで賄える件数」を数え、実際に1〜2件生成してみせる
3. **並列立案 ＋ 敵対検証 → 裁定パッケージ** — 案ごとに「実装立案（実際に旗艦コードを読ませる）」→「敵対検証（効果 / コスト5層での読み替え / ロードマップ重複 / 事実誤りリスク / スコープ）」を流し、**本丸 / 別枠 / 見送り ＋ 実装順 ＋ 最初の一手**に仕分ける
4. **旗艦実装（層1 から）** — 最初の一手はコスト0の層から入る。エンジン改修は後続案の共通レールを意識して切る。実装と同時に検証コマンドの実出力を残す
5. **別の目で検収 → 反映** — 実 API 打鍵・正本突合・退行・攻撃面・全件スイープの反例探しを渡し、実出力で合否を出させる
6. **品質ゲート化** — 採点器を監査スクリプトにし、再起動の鎖（テスト → 品質ゲート → 再起動 → UI 検証 → スモーク）に組み込む。基準値の初期化・悪化時の自己緑化の拒否・旧経路の封鎖まで
7. **横展開 ＋ 還流** — ここからは `franchise-kaizen` の展開・検収・還流に接続する

## スコープ外

エンジン・UX・データ設計の改善 → `franchise-kaizen` / 単発の事実誤り監査 → `kansa`（この型は「質を上げる」であって「誤りを潰す」専門ではない。ただし正本突合は事実誤りも拾う）
