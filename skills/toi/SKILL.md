# toi — 問いを通す

> **この手順は自前の台帳・検査スクリプトを前提とする。** 同梱していないので、無い場合は同じ項目を手動で確認する（何を確認すべきかは各手順に書いてある）。

正本 = `../../docs/institutions/question-catalog.md`。**まず正本を読む**（記憶で問いに答え始めない）。

この型は2点で普通の質問リストと違う。

1. **問いの掲載資格**: 問いを追加するには、**その問いが過去に実際に判断を変えた実績（出典）**が要る。出典のない問いを載せてはいけない
2. **回答の機械ゲート**: 回答は会話に流さずファイルに書き、決定論スクリプトが形式と接地を検査する。通らない限り**未回答**として扱う

## 手順

1. 症状の索引から、いまの詰まりに一番近い行を選ぶ
2. **接地**: 対象の実物を開く（事業フローの正本・作業キュー・直近の報告や決定ログ）。**開いていないものを事実欄に書かない**
3. 回答ファイルを書く。1問 = **事実 / 判定 / 一手**の3欄
   - 事実欄には、開いた実物からの引用・数字・パスを最低1つ。無ければ「計測なし（探した場所: …）」と書く（**探さずに無いと言うのを禁止する**）
4. 機械ゲートを実行し、**合格の実出力を貼る**（不合格のまま答えを出さない）
5. 一手をキューに積む（外向き・不可逆・お金は人間ゲートなので、積まずに裁定パッケージへ）
6. 正本末尾の「問いの効き目ログ」に1行追記する（裁定IDか、変えなかった理由。IDなしの「効いた」は無効）

## 禁止

- 正本を読まずに記憶で問いに答えること
- 回答を会話に流して終わること（ファイルと合格の実出力が無ければ未回答）
- 裁定に使う回答の出典照合を、回答者自身がやること（自己検収の禁止の問い版）
