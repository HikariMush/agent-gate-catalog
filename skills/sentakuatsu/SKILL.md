# sentakuatsu — 選択圧をかけて設計案を進化させる

対訳: **evolutionary search / genetic algorithm ＋ LLM**（reflective prompt evolution・Pareto 選択）。禁止事項の根拠は **Goodhart's law / reward hacking**。

対象はプロンプトではなく**設計案そのもの**（書式・指標・ゲート・プロトコル）。

## 手順

1. **入口ゲート**: 設計問題を1行に固定し、採点器が次の3形態のどれで実在するか確認する。**無ければ回さない**
   - (a) 結末が既知のテストセット
   - (b) 対象ドメインで校正済みの判定器
   - (c) 固定の攻撃セット
   採点器が無い場合は、採点器の構築を先に走らせ、構築した採点器を裁定パッケージに組んで人間の裁定に通す（**進化の方向を決める唯一の点**なので、明示回答なしに開始しない）
2. **実行前宣言**: 体数の試算・採点器の形態・対照鎖の有無を宣言してから回す
3. **形態(a)の選定ゲート（実施痕が必須）**: ラベル監査・漏洩チェック・予見的検証分の蓄積をすべて実施し、実行したコマンドと実出力を成果物に貼る
4. **進化ループ**: 観点割り当ての初期生成（相互不可視）→ 多様性判定 → 初期採点 → [選択 → 立場固定の変異 → 採点] の世代ループ → 停止条件
5. **出力**: 裁定パッケージ5点形式 ＋ 系譜（どの立場の変異が効いたか・多様性判定の結果）＋ **「この採点器が測れていないもの」欄（必須）**。形態(a)の最終スコアは検証分で報告し、学習分との乖離（過適合の兆候）を明記する
6. **書き戻し**: 成果物を1ファイルに（問題1行・採点器・選定ゲートの実施痕・系譜・勝者・盲点）。実行結果（進化が初期案に勝ったか）を1行追記する。無益が続くならこの型自体の廃止判定が発火する
7. **勝者案の検収はこのスキルの外**（自己検収の禁止）

## 事故の形（実際に検出されたもの）

**ホールドアウト漏洩**: 「最終検証まで隠す」はずの検証事例の結末が、全エージェントの起動時に自動ロードされる文脈に既に載っており、過適合の検出力がゼロのまま「合格」が出る構造だった。**隠しデータで検証する設計では、配布物に加えて、自動ロードされる文脈への漏洩も検索で確認し、実施痕を残す。**

## 禁止

- 採点器なしでの実行（選択圧のない多エージェント議論は一般論への漂流を生むだけ）
- 世代の途中で採点器を変えること（動く的）
- 漏洩チェック未実施のまま検証分スコアを「汎化」として報告すること
- 最終報告から「採点器の盲点」欄を省くこと
- 実行した本人が勝者案に合格を出すこと
